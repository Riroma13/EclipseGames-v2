# REDESIGN BRIEF — EclipseGames Next

## Objetivo

Crear una V2 que se sienta como una herramienta docente rápida, clara y moderna, no como un panel técnico con gamificación añadida.

## Qué podemos cambiar

Se permite replantear:
- arquitectura de navegación;
- layout general;
- dashboard;
- cards;
- paneles laterales;
- flujos de registro;
- jerarquía de información;
- densidad visual;
- visualización de estados;
- gestión de grupos;
- entrada de RT;
- registro de XP;
- Show Student;
- modo proyección;
- narrativa;
- feedback y confirmaciones;
- funcionalidades cuando mejoren claramente el uso real.

## Qué no debemos hacer

- copiar la UI anterior por inercia;
- cambiar reglas de negocio para encajar un diseño bonito;
- introducir complejidad administrativa innecesaria;
- convertir gamificación en ruido;
- hacer flujos con demasiados clics;
- esconder información crítica detrás de navegación profunda;
- sacrificar privacidad por comodidad.

## Problemas a resolver

### Uso en directo
La interfaz debe responder al ritmo de una clase.

### Jerarquía
Distinguir claramente:
- información que necesito ahora;
- seguimiento;
- evaluación;
- gamificación;
- configuración.

### Densidad
Evitar tanto pantallas vacías como dashboards saturados.

### Proyección
Debe sentirse como una experiencia separada y segura.

### Narrativa
Debe tener personalidad propia sin dominar el producto.

## Funcionalidad a reconsiderar

Codex puede proponer mejoras sobre:
- navegación grupo/alumno;
- bulk actions;
- accesos rápidos;
- undo;
- feedback inmediato;
- gestión de sesiones;
- historial contextual;
- visualización de progreso;
- paneles de evaluación;
- activación de proyección;
- Show Student.

Cada cambio funcional debe explicar:
1. problema actual;
2. propuesta;
3. impacto;
4. riesgo;
5. cómo conserva `PRODUCT-CONTRACT.md`.

## Entregable de diseño inicial

Antes de construir todo:
- mapa de información;
- 3 direcciones visuales resumidas;
- elegir 1;
- prototipo de login, workspace de grupo, panel de alumno, acción rápida, RT masivo, proyección, Show Student y narrativa;
- validar esos flujos antes de expandir.
